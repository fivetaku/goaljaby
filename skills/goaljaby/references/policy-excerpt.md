# Policy Excerpt — goaljaby 번들 정책 발췌

> 이 파일은 goaljaby 플러그인이 인용하는 정책 섹션을 **플러그인 안에 번들**한 것이다.
> `shared/` 디렉토리는 설치 시 플러그인 캐시에 포함되지 않으므로, 런타임 참조는 이 파일을 기준으로 한다.

## Language Policy 발췌 (원본: shared/language-policy.md)

### §1. 출력 언어 결정 — 자동 감지 (Language Lock)

매 호출마다 새로 판단하고 **저장하지 않는다**. 본문을 읽기 전에 언어를 먼저 잠근다(`output_lang`).

1. **요청에 텍스트가 있으면** → 그 텍스트의 언어 (`/x 만들어줘` → 한국어, `/x make it` → 영어).
2. **요청 텍스트가 없으면** → 직전까지 사용자가 쓰던 대화 언어 (이미 컨텍스트에 있음).
3. **새 세션 + 빈 호출**(텍스트도 직전 대화도 없음) → 영어로, 또는 한 번만 어느 언어인지 물어본다.

> **한국에서 만들어졌다는 이유로 한국어를 기본값으로 두지 말 것.**

감지된 `output_lang`은 사용자에게 보이는 **모든 산출물**에 적용된다: 대화 응답, 설명/코칭, 상태 메시지, 그리고 **디스크에 쓰는 문서**(헤딩·본문 포함).

### §2. 식별자는 번역하지 않는다

언어를 바꿔도 그대로 두는 것: 파일명, 명령어/플래그, 코드, 슬롯 토큰(`{SLOT}`), 약어/고유명사(`PRD`, `SDD`, `JWT`, `viewport`, `scope`, `public API`, `DB 스키마`), URL.

### §3. AskUserQuestion 라벨도 사용자 언어로

`question` / `header` / `label` / `description` 전부 `output_lang`으로 **번역해서** 호출한다.
스킬 파일 안의 JSON 예시는 **템플릿**이다 — 그대로 내보내지 말고 감지 언어로 옮긴다.

### §5. 디스크 산출물 + 결정론적 검증

문서를 파일로 쓰는 플러그인(goaljaby, insane-design 등)은 산출물도 `output_lang`으로 생성한다.

검증 로직이 헤딩/언어를 grep으로 확인한다면, **고정 언어 가정(=한국어)을 버리고 `output_lang` 기준으로 반전**한다:
- 언어별 **헤딩 세트**(canonical heading map)를 정의해 두고, 생성물의 헤딩이 감지 언어 세트에 속하는지 검증.
- 한국어/영어는 1급 지원(결정론적 grep 가능). 그 외 언어는 헤딩 세트가 없으면 **섹션 존재(개수) 검증**으로 폴백하고, 그 한계를 사용자에게 알린다(침묵 폴백 금지).

## Questioning Policy 발췌 (원본: shared/questioning-policy.md)

### §1. 공통 규칙 (모든 인터뷰형 플러그인)

1. **묻지 말고 추론** — 최초 입력·맥락에서 추론 가능한 건 질문하지 않는다. 물어야 하면 "기본값 제시 + 확인"으로(예: "모바일 앱으로 가정할게요 — 아니면 말씀 주세요").
2. **핵심 먼저, 한 번에 하나** — 정보가치 가장 높은 질문을 앞에(뒤로 갈수록 답이 짧고 균일해짐=satisficing). 열린 질문은 한 번에 하나. (단순 "분류/설정 고르기"는 객관식 카드가 더 낫다.)
3. **과거 행동 > 가정** — "이 기능 쓰실래요?"(가정·X) 대신 "지금은 이 문제를 어떻게 해결하세요?"(과거 실제 행동·O). [The Mom Test]
4. **"왜" → "무엇/어떻게"** — "왜 그랬어요?"는 방어를 유발. "거기서 무엇을 하려던 거였어요?"로.
5. **답을 되짚어라(반영)** — 다음 질문 전에 직전 답을 한 문장으로 반영. 신뢰↑·마찰↓. [OARS]

### §2a. 조기 종료 금지 (모든 new 설계의 #1 실패 모드)

- **첫 답변에서 끊지 마라.** 사용자가 표면적·예의상·회피성으로 답하면 그걸 결론으로 채택하지 말 것.
- 사용자가 **진짜 결과**(real need / 스스로의 통찰 / 실제 이해)에 **본인 발화로 도달**할 때까지 턴을 이어간다. 에이전트가 "이해했다"고 단정하는 건 금물.
- **간결함은 "사용자 확인"에 종속된다.** 마찰 최소화가 과해지면 도달 직전에 끊긴다.

### §2c. 과잉 가드 (역방향 — 2a와 균형)

- 사용자가 **이미 스스로 진단**했거나, **요청이 이미 충분히 구체적**이거나, **직접 답/명령어를 명시적으로 원하면** → 더 캐묻지 말고 **즉시 제공**하라. 과잉 질문/코칭/교육 = 마찰 실패. [k6-clear / p4-aware / p3-pragmatist 검증]
- 구분 신호: 답이 *표면/회피* → 더 (2a/2b). 답이 *진짜 도달/직접 요청* → 멈춤(2c).
